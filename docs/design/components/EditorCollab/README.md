# Comments and suggestions

Google Docs–style collaboration (part 6), in the margin rail (E.6).

- **Modes** (header): **Editing** changes the document directly; **Suggesting** turns every edit into a suggestion; **Viewing** reads and comments. People without edit permission get Suggesting, with Editing locked and a way to ask an owner (E.10). The mode button is on the tint while suggesting, so it's never forgotten.
- **Suggestions:** inserted text is in the main colour with a dashed underline; deleted text is struck through in the error colour and stays visible; both are dashed because they haven't happened (the rule from 2.4). Each change gets a card: who, what ("Replace 30 days with 14 days", "Add …", "Delete …"), Accept and Reject. The rail header's All menu accepts or rejects everything, or everything from one agent. Formatting changes in Suggesting are suggestions too.
- **Comments:** select text, then Comment (⌥⌘M, the bubble or the toolbar). The text gets the warning tint with a warning underline, on screen only, never printed and distinct from the highlight colour (E.39); the card quotes it, takes @mentions of people (notified) and agents, and offers Comment and Cancel. Threads show replies; **Resolve** files the thread away (the highlight goes; "1 resolved" in the rail header; Reopen brings it back). Resolved threads stay in the document's history.
- **The rail:** cards sit beside their text and stack without overlapping; clicking a card or its text makes both active (the card lifts and moves out, the highlight deepens). Under 1024px the cards move to a drawer with All, Comments, Suggestions and Resolved.
- **Who decides:** anyone who can edit accepts or rejects any suggestion, an agent's included; each decision is logged with their name (E.29).
- **Publishing a template:** suggestions must be accepted or rejected first (E.37); open comments stay on the draft and never print.
