- **Workspace plugins can act by themselves (plugin SDK 1.53).** A workspace plugin can declare automations, such as "when an order is confirmed, stamp it, create a baking task and tell the bakers". A trigger is a record being created, changed (or one field changing) or moved into a state, with an optional condition. The steps are set fields, create a record, move, and notify a role or a person. Automations run in the background, as the plugin acting for the person who caused the change, and only with what that person may do. Each step happens once even when a run is retried. A loop of automations triggering each other stops after three hops, and every run keeps a trace of each step and why it stopped, readable at `/api/v1/workspace-plugins/{plugin}/automation-runs`. A plugin's automations can be switched off on their own (WHIT-763).
